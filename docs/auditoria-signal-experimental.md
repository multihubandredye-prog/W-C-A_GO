# Isolated Signal store experiment — not for production

Experimental flag `WCA_EXPERIMENTAL_PRIMARY_SIGNAL_STORE=true` bypasses opening and applying `DB_KEYS_URI`, so a newly paired device uses its primary store both when created and after restart. Default is false. Existing secondary identities, sessions, prekeys, sender keys and message secrets are NOT migrated; never enable on an existing account or existing database. Use only a new, isolated, persistent primary database, separate storage, and a separate test account. Do not overwrite, delete, or import production databases. No automated migration or rollback is provided.

This is a prototype, not a proven fix. The primary DB contains sensitive private key material; keep it in app-private storage with restricted access, protect database and SQLite WAL/SHM sidecars, and plan consistent backups. Central's env writer may drop unknown settings. No UI integration has been implemented. The flag does not make a memory DB persistent; use a correctly configured private persistent SQLite DB. Abrupt termination and SQLite durability require additional testing. The pairing lifecycle, Signal interoperability, messages, groups, inbound/outbound calls, and webhook behavior must be tested with real isolated accounts before adoption. Never copy a stale database over a live session. Restore and migration require a separately designed and authorized procedure.
